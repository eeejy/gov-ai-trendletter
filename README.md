# 공공기관 AI 동향지 반자동화

주 1회, 정부·산업·개발자 동향을 모아 **기관 업무 영향도를 반영한 AI 동향지**를 만든다.
수집·통합·초안 작성은 자동, **선별과 발행은 사람이** 한다.

> **[▶ 결과물 예시 보기](data/issues/demo/)** — 실제로 생성된 동향지 1건 (단일 HTML, 내려받아 열면 그대로 보인다)

---

## 왜 만들었나

AI 정책·기술 환경이 빠르게 바뀌는데, 기관이 그걸 따라가는 방식은 대개 이렇다.

- 담당자가 매주 손으로 기사를 찾아 읽고 고른다
- 무엇을 봤고 왜 그걸 골랐는지가 기록되지 않는다
- 담당자가 바뀌면 기준도 함께 사라진다

이 도구는 그 과정을 **기록 가능한 파이프라인**으로 만든다.
어느 수집원이 무엇을 가져왔고, 어떤 기준으로 몇 건을 걸렀으며, 왜 이 6건을 골랐는지가
발행물과 감사 도구에 그대로 남는다.

## 무엇을 하나

```
15개 수집원  →  중복 통합  →  AI 주제 확인  →  중요도 산출  →  6건 선별  →  Claude 초안  →  검토·발행
   400여 건      330 이슈       160 이슈         8개 요소         트랙 배분      본문·시사점      사람이 확정
```

- **정책** — 정책브리핑 부처코드 검색(57개 부처), 기관 게시판, 지자체·해외 정책 플랫폼
- **산업** — AI 전문지 RSS, IT 매체 목록, 뉴스 애그리게이터
- **개발자** — Hacker News, Reddit, GitHub

## 어떤 문제를 어떻게 풀었나

실제로 돌려 보고 고친 것들이다. 자세한 근거 수치는 [`docs/pipeline.md`](docs/pipeline.md)에 있다.

| 문제 | 어떻게 알았나 | 어떻게 고쳤나 |
| --- | --- | --- |
| 부처별 검색이 엉뚱한 자료를 가져옴 | `경찰청 인공지능` 검색 12건이 전부 다른 부처 자료 | 본문 전문검색이라 부처가 안 걸러짐 → **부처코드(repCode)** 도입 |
| 같은 사건이 여러 건으로 쪼개짐 | 한 모델 소식이 7개 이슈로 분산 | 제목 유사도만으론 영어 기사가 안 묶임 → **제품 이름 2차 병합** |
| 개인 후기가 대표 기사가 됨 | 커뮤니티 경험담이 모델 발표 소식을 제침 | **뉴스성 판정** — 발표·공개는 가점, 1인칭 후기는 감점 |
| 업무 관련도가 사실상 0 | 160개 이슈 중 141개가 0점 | 현업 낱말만 봤음 → **지난 발행본 분석**으로 관점 재설계 |
| 특정 기관이 과대평가 | 지난 발행본에 0건인 기관이 정책 1위 | 유사기관을 **등급**으로 나눔 |
| 초안이 빈 문장 | `적용 가능성 검토 필요` 수준 | 프롬프트에 **지난 발행본 실제 문장**을 예시로 |

## 쓰는 법

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
python run.py doctor          # 준비가 다 됐는지 한 번에 점검
python run.py editor          # 로컬 웹 편집기 (127.0.0.1:8765)
```

편집기에서 **이번 주 동향지 만들기** → 항목 손질 → **미리보기** → **확정본 만들기** → **내려받기** 또는 **텔레그램 전송**.
전체 3~5분이며 진행 상황이 단계별로 표시된다.

확정본은 `data/issues/` 에 단일 HTML 파일로 남는다. 텔레그램을 쓰지 않고
메일·메신저로 직접 돌리려면 **내려받기** 로 파일만 챙기면 된다.

편집 내용은 고칠 때마다 자동 저장되고, 저장 직전 내용을 20개까지 남겨 둔다.
잘못 지웠으면 상단 **되돌리기** 로 그 시점으로 돌아갈 수 있다.

```bash
python run.py doctor          # 설치·설정·연결 상태 한 번에 점검
python run.py sources         # 수집원 접속 점검
python run.py draft --days 7  # 수집 + 초안 (CLI)
python run.py telegram        # 텔레그램 문구 미리보기
python tools_audit.py         # 무엇을 가져와 무엇이 실렸는지 추적
python tools_sources.py       # 수집원 현황 + 라이브 점검
python tools_schedule.py      # 매주 정해진 시각에 초안 자동 생성 예약
```

## 결과물

**완전한 스탠드얼론 HTML 한 장**(약 260KB). 글꼴·CSS·JS 를 모두 담고 있어
인터넷 없이도 열린다. 받아보는 사람은 브라우저 외에 아무것도 설치하지 않는다.
전달 방법은 [`docs/deploy.md`](docs/deploy.md) 참고.

1. **표지** — 별이 흐르는 다크 화면
2. **이번 주 요약** — 한 문장 요약 + 트랙별 후보/게재 + 많이 나온 말
3. **성운 목차** — 이번 호 항목은 밝은 별과 제목, 나머지 수집분은 낱말로.
   색이 수집 트랙(정책/산업/개발자)을 나타낸다. 모바일에서는 터치 목록으로 바뀐다
4. **본문** — 선정 사유와 관련 기사 링크 포함

글꼴은 **그 회차에 쓰인 글자만 잘라** 파일에 담는다(약 200KB). 글꼴이 없는 PC에서도 같게 보인다.

## 구조

```
config/     settings·sources·ontology·부처코드   ← 기관에 맞게 바꾸는 곳
config/examples/                                  도메인 적용 예시
prompts/    항목 초안 · 핫이슈 종합 · 텔레그램
templates/  issue.html.j2  발행물 서식
src/trendletter/
  collectors/  gov·news·dev      수집원별 파서
  dedupe.py    같은 사건 통합
  scoring.py   AI 관문 · 업무 관련도 · 중요도
  pipeline.py  수집 → 통합 → 선별 → 초안
  llm.py       Claude Code CLI 호출
  telegram.py  요약 발송
  editor/      로컬 웹 편집기 (Flask)
docs/       설계·검증·수집원 현황·배포
```

## 기관에 맞추려면

1. `config/settings.yaml` — 기관명·발행 주기·구성 건수
2. `config/sources.yaml` — 수집원. 정책브리핑은 `depts` 에 부처명만 적으면 된다
3. `config/ontology.yaml` — **업무 관련도**. `config/examples/` 참고

세 번째가 핵심이다. **지난 발행본을 먼저 분석해서** 실제로 무엇을 실었는지 확인하고
그 분포에 가중치를 맞추는 것을 권한다. 감으로 정하면 엉뚱한 기관이 상위로 올라온다.

## 필요한 것

- Python 3.9+
- [Claude Code](https://claude.com/claude-code) — 초안 작성용. 없으면 규칙 기반 뼈대만 나온다
- 텔레그램 봇 토큰 (선택) — [`docs/telegram.md`](docs/telegram.md)

## 자동 실행

초안 생성까지만 예약하고 **발행은 사람이 누른다.**
GitHub Actions 는 쓰지 않는다 — 공개 저장소 로그에 초안이 남고,
검토 없이 나가면 잘못된 내용이 전 직원에게 전달되기 때문이다.

```bash
python tools_schedule.py --day 5 --time 08:00   # macOS launchd / Windows 작업 스케줄러
```

예약된 시각에 수집·초안이 만들어지고 **담당자에게만** 텔레그램 알림이 간다.
자세한 내용은 [`docs/telegram.md`](docs/telegram.md).
