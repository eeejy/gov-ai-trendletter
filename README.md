# 정보동향지 반자동화

분야를 설정하면 그 분야 동향지가 나온다. AI 동향지도, 국제협력 동향지도,
해양안전 동향지도 **같은 프로그램으로** 만든다.

수집·통합·초안 작성은 자동, **선별과 발행은 사람이** 한다.

> **[▶ 결과물 예시 보기](data/issues/demo/)** — 실제로 생성된 동향지 1건
> (단일 HTML, 내려받아 열면 그대로 보인다)

> ### 📄 [**이게 무엇이고 어떻게 도는지 — 설명자료**](https://htmlpreview.github.io/?https://raw.githubusercontent.com/eeejy/gov-ai-trendletter/main/docs/%EC%84%A4%EB%AA%85%EC%9E%90%EB%A3%8C.html)

## 왜 만들었나

정책·기술 환경이 빠르게 바뀌는데, 기관이 그걸 따라가는 방식은 대개 이렇다.

- 담당자가 매주 손으로 기사를 찾아 읽고 고른다
- 무엇을 봤고 왜 그걸 골랐는지가 기록되지 않는다
- 담당자가 바뀌면 기준도 함께 사라진다

이 도구는 그 과정을 **기록 가능한 파이프라인**으로 만든다.
어느 수집원이 무엇을 가져왔고, 어떤 기준으로 몇 건을 걸렀으며, 왜 이걸 골랐는지가
발행물과 감사 도구에 그대로 남는다.

## 어떻게 쓰나

### 1. 프로그램 받기

[**Releases**](../../releases) 에서 내 것을 받는다. 파이썬은 필요 없다.

| | 받을 것 | 여는 법 |
| --- | --- | --- |
| **맥** (M1 이후) | `trendletter-macos-arm64.zip` | 풀고 `동향지.app` **오른쪽 클릭 → 열기** |
| **맥** (Intel) | `trendletter-macos-intel.zip` | 〃 |
| **윈도우** | `trendletter-windows.zip` | 풀고 `trendletter.exe` |
| **소스에서** | — | `python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt` |

맥은 처음 열 때 그냥 더블클릭하면 "확인되지 않은 개발자" 라며 막힌다.
**오른쪽 클릭 → 열기 → 열기** 로 한 번만 열면 그다음부터는 더블클릭으로 열린다.
칩을 모르겠으면 애플 메뉴 → «이 Mac에 관하여» 에서 본다.

설정과 산출물은 프로그램 안이 아니라 사용자 폴더에
쌓이므로(맥 `~/Library/Application Support/동향지`, 윈도우 `%APPDATA%\동향지`)
프로그램을 새로 받아도 설정은 그대로 남는다.

### 2. 설정 — 처음 한 번

첫 실행이면 설정 화면부터 열린다. 순서대로 채우면 된다.

```
말로 설정 → ① 기관 → ② 수집원 → ③ 키워드 → ④ 관련도 → ⑤ 구성 → ⑥ 모델 → ⑦ 시험
```

**말로 설정하기** — 맨 위 칸에 한두 문장 적으면 ①~⑤를 한 번에 제안한다.

> 해양 안전과 선박 사고 예방을 다루는 동향지.
> 우리는 해양경찰청이고 현장 구조·단속 업무에 닿는 소식이 중요하다.

이렇게 적으면 핵심어 22개, 부처별 수집원 7곳, 트랙 3개, 관련도 8그룹이
가중치와 함께 나온다. **바로 적용되지 않는다** — 제안을 보여 주고 고른 것만
반영한다. 설정이 소리 없이 바뀌면 왜 그렇게 됐는지 아무도 모르기 때문이다.

각 단계마다 **시험** 단추가 있다. 수집원은 실제로 몇 건 들어오는지, 키워드는
몇 건이 통과하는지, 모델은 연결이 되는지 그 자리에서 확인한다.
마지막 ⑦ 에서는 지금 설정 그대로 돌려 **무엇이 실릴지 미리 본다**(초안은 쓰지
않아 돈이 안 든다).

### 3. 만들기

**이번 호 만들기** → 항목 손질 → **미리보기** → **확정본 만들기** → **텔레그램 전송**.
전체 3~5분이며 진행 상황이 단계별로 표시된다.

확정본은 `data/issues/` 에 단일 HTML 파일로 남는다. 텔레그램을 쓰지 않는다면
**폴더 열기** 로 그 파일을 꺼내 메일·메신저에 첨부해도 결과물은 같다.

편집 내용은 고칠 때마다 자동 저장되고, 저장 직전 내용을 20개까지 남겨 둔다.

## 분야 하나가 폴더 하나다

```
profiles/
  ai/                   AI 동향지 (17호까지 실제 발행)
    profile.yaml        트랙·관문·감점
    sources.yaml        수집원
    ontology.yaml       업무 관련도
    lexicon.yaml        분야 낱말 사전
    prompts/            이 분야 전용 프롬프트 (없으면 공통을 쓴다)
  intl-coop/            국제협력 동향지
```

코드는 분야를 모른다. 무엇을 모으고 무엇을 중요하게 볼지는 전부 이 폴더가
정한다. `intl-coop` 는 **코드를 한 줄도 고치지 않고** 만든 두 번째 분야다.

낱말 사전이 비어 있어도 죽지 않는다 — `intl-coop` 의 `vendors` 는 실제로
빈 목록이고, 그래도 파이프라인은 끝까지 간다.

## 무엇을 어떻게 고르나

```
수집원  →  중복 통합  →  분야 관문  →  중요도 산출  →  트랙별 배분  →  모델 초안  →  검토·발행
```

규칙 점수로 후보를 좁히고(재현 가능), 그 안에서 모델이 본문을 읽고 고른다.
항목마다 규칙 순위와 선정 사유가 함께 남는다 — [docs/pipeline.md](docs/pipeline.md)

**관련도**가 핵심이다. 같은 분야 자료라도 우리 업무에 닿는 것이 위로 와야 한다.
그룹마다 가중치를 주고, 흔한 말에는 `context` 를 달아 그 맥락일 때만 세게 한다.

```yaml
현장업무:
  weight: 5.0
  keywords: [구조, 수색, 단속, 순찰, 출동]
  context: [해상, 해양, 선박, 어선, 연안, 항만]   # 이 말이 함께 있을 때만
```

> **지난 발행본을 먼저 분석해서** 실제로 무엇을 실었는지 확인하고 그 분포에
> 가중치를 맞추는 것을 권한다. 감으로 정하면 엉뚱한 기관이 상위로 올라온다.
> AI 프로파일의 가중치는 실제로 그렇게(11개 호 57개 항목 분포 분석) 나왔다.

## 초안 모델 — 넷 중에서 고른다

| | 키 | 비용 |
| --- | --- | --- |
| **Claude Code CLI** | 필요 없음 (쓰던 구독 그대로) | 구독에 포함 |
| **Claude / GPT / Gemini API** | 필요 | 종량 |
| **Ollama** (내 컴퓨터) | 필요 없음 | 무료 |

설정 화면 ⑥ 에서 고르고 **시험** 을 누르면 그 자리에서 연결을 확인한다.
어느 것을 고르든 파이프라인은 바뀌지 않는다. 모델이 없어도 수집·선별은
그대로 되고 초안만 규칙 기반 뼈대로 나온다.

## 결과물

**완전한 스탠드얼론 HTML 한 장**(약 260KB). 글꼴·CSS·JS 를 모두 담고 있어
인터넷 없이도 열린다. 받아보는 사람은 브라우저 외에 아무것도 설치하지 않는다.

1. **표지** — 별이 흐르는 다크 화면
2. **이번 호 요약** — 한 문장 요약 + 트랙별 후보/게재 + 많이 나온 말
3. **성운 목차** — 이번 호 항목은 밝은 별과 제목, 나머지 수집분은 낱말로.
   색이 트랙을 나타낸다. 모바일에서는 터치 목록으로 바뀐다
4. **본문** — 선정 사유와 관련 기사 링크 포함

글꼴은 **그 회차에 쓰인 글자만 잘라** 파일에 담는다(약 200KB).

## 어떤 문제를 어떻게 풀었나

실제로 돌려 보고 고친 것들이다. 근거 수치는 [`docs/pipeline.md`](docs/pipeline.md).

| 문제 | 어떻게 알았나 | 어떻게 고쳤나 |
| --- | --- | --- |
| 부처별 검색이 엉뚱한 자료를 가져옴 | `경찰청 인공지능` 검색 12건이 전부 다른 부처 자료 | 본문 전문검색이라 부처가 안 걸러짐 → **부처코드(repCode)** 도입 |
| 같은 사건이 여러 건으로 쪼개짐 | 한 모델 소식이 7개 이슈로 분산 | 제목 유사도만으론 영어 기사가 안 묶임 → **제품 이름 2차 병합** |
| 개인 후기가 대표 기사가 됨 | 커뮤니티 경험담이 발표 소식을 제침 | **뉴스성 판정** — 발표·공개는 가점, 1인칭 후기는 감점 |
| 업무 관련도가 사실상 0 | 160개 이슈 중 141개가 0점 | 현업 낱말만 봤음 → **지난 발행본 분석**으로 관점 재설계 |
| 특정 기관이 과대평가 | 지난 발행본에 0건인 기관이 정책 1위 | 유사기관을 **등급**으로 나눔 |
| 초안이 빈 문장 | `적용 가능성 검토 필요` 수준 | 프롬프트에 **지난 발행본 실제 문장**을 예시로 |
| 분야를 바꿔도 AI 글만 들어옴 | 국제협력 설정으로 해커뉴스가 계속 AI 기사만 | 수집기 코드에 낱말이 박혀 있었음 → **`params.include_pattern`** 으로 |
| 설정을 한 번 저장하면 주석이 사라짐 | `sources.yaml` 주석 56줄이 날아감 | YAML 을 통째로 갈아치우고 있었음 → **제자리 병합** |

## 터미널로 쓰기

```bash
python run.py doctor          # 준비가 다 됐는지 한 번에 점검
python run.py editor --setup  # 설정 화면
python run.py editor          # 편집기
python run.py sources         # 수집원 접속 점검
python run.py draft --days 7  # 수집 + 초안
python run.py telegram        # 텔레그램 문구 미리보기
python tools_audit.py         # 무엇을 가져와 무엇이 실렸는지 추적
python tools_schedule.py      # 매주 정해진 시각에 초안 자동 생성 예약
```

## 직접 빌드하기

```bash
./installer/build_mac.sh      # dist/동향지.app  (이 맥의 칩용)
```

PyInstaller 는 크로스 컴파일이 안 된다 — 맥에서 윈도우 exe 를 만들 수 없고,
인텔용을 애플실리콘에서 만들 수도 없다. 그래서 배포본은 GitHub Actions 에서
세 러너로 나눠 만든다(`windows-latest` · `macos-14` · `macos-13`).
태그(`v*`)를 밀면 셋을 모아 Releases 에 올린다. 하나라도 실패하면 릴리스를
만들지 않는다 — 반쪽짜리 릴리스보다 낫다.

> **초안은 Actions 에서 만들지 않는다.** 공개 저장소 로그에 초안이 남고,
> 검토 없이 나가면 잘못된 내용이 전 직원에게 전달되기 때문이다.
> 액션이 하는 일은 **빌드뿐**이며 수집도 초안 작성도 하지 않는다.

## 자동 실행

초안 생성까지만 예약하고 **발행은 사람이 누른다.**

```bash
python tools_schedule.py --day 5 --time 08:00   # macOS launchd / Windows 작업 스케줄러
```

## 필요한 것

- 설치형을 쓰면 아무것도 없어도 된다
- 소스로 쓰면 Python 3.9+
- 초안용 모델 — 넷 중 하나 (없어도 규칙 기반 뼈대는 나온다)
- 텔레그램 봇 토큰 (선택) — [`docs/telegram.md`](docs/telegram.md)
